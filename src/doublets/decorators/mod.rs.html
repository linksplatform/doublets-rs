1//! Zero-cost decorators that add policy to any [`Doublets`](crate::Doublets) store.
2//!
3//! This module is a port of the decorator layer of `Platform.Data.Doublets`. Each C#
4//! decorator has a counterpart here with the same logic, but composition is static: a
5//! decorator is a generic struct that owns the store it wraps, every forwarding method is
6//! `#[inline]`, and the policy markers are zero-sized. A chosen stack is one concrete
7//! type, so the optimiser can fuse the whole stack into a single `create` / `update` /
8//! `delete` / `each` with no per-layer call.
9//!
10//! # Building a stack
11//!
12//! [`DecoratorsExt`] takes the store by value and returns the concrete composed type:
13//!
14//! ```rust
15//! use doublets::{decorators::{DecoratorsExt, Resolve}, mem, unit, Doublets};
16//!
17//! # fn main() -> Result<(), Box<dyn std::error::Error>> {
18//! let mut store = unit::Store::<usize, _>::new(mem::Global::new())?
19//!     .with_uniqueness(Resolve)
20//!     .with_usages_validation();
21//!
22//! let a = store.create_point()?;
23//! let b = store.create_point()?;
24//! assert_eq!(store.create_link(a, b)?, store.create_link(a, b)?);
25//! # Ok(())
26//! # }
27//! ```
28//!
29//! # The decorators
30//!
31//! | C# decorator | This module | Create | Update | Delete | Each |
32//! |---|---|:--:|:--:|:--:|:--:|
33//! | `LinksUniquenessValidator` | [`UniquenessValidator`] | | ● | | |
34//! | `LinksUniquenessResolver` | [`UniquenessResolver`] | | ● | | |
35//! | `LinksCascadeUniquenessAndUsagesResolver` | [`CascadeUniquenessAndUsagesResolver`] | | ● | ● | |
36//! | `LinksUsagesValidator` | [`UsagesValidator`] | | ● | ● | |
37//! | `LinksCascadeUsagesResolver` | [`CascadeUsagesResolver`] | | | ● | |
38//! | `LinksInnerReferenceExistenceValidator` | [`InnerReferenceExistenceValidator`] | | ● | ● | ● |
39//! | `LinksItselfConstantToSelfReferenceResolver` | [`ItselfConstantToSelfReferenceResolver`] | | ● | | ● |
40//! | `LinksNullConstantToSelfReferenceResolver` | [`NullConstantToSelfReferenceResolver`] | ● | ● | | |
41//! | `LinksNonExistentDependenciesCreator` | [`NonExistentDependenciesCreator`] | | ● | | |
42//! | `NonNullContentsLinkDeletionResolver` | [`NonNullContentsLinkDeletionResolver`] | | | ● | |
43//! | `LoggingDecorator` | [`LoggingDecorator`] | ● | ● | ● | |
44//! | `NoExceptionsDecorator` | [`NoExceptionsDecorator`] | ● | ● | ● | ● |
45//!
46//! # Ordering
47//!
48//! C# propagates a `_facade` reference down the stack so that a decorator's recursive
49//! calls — a cascading delete, a usage merge — re-enter at the *top* of the stack. A
50//! statically composed stack has no such back-reference: a decorator only knows the
51//! layers below it, so recursive calls re-enter at the layer that made them.
52//!
53//! For a stack whose outermost layer is the one doing the recursion the two are the same,
54//! which is the case for every stack C# itself builds. Otherwise, put a decorator whose
55//! behaviour the cascade must observe *below* the decorator that cascades.
56//!
57//! # Deviations from C\#
58//!
59//! Each is documented on the item it affects; in summary:
60//!
61//! - [`UniquenessResolver`] reports the surviving link to the handler, so
62//!   [`create_link`](crate::Doublets::create_link) returns a valid address instead of the
63//!   address of the link it just deleted.
64//! - [`CascadeUsagesResolver`] tracks the links it has already visited, so a reference
65//!   cycle terminates instead of overflowing the stack.
66//! - `MergeUsages` re-points sources and targets correctly; the C# version writes null
67//!   targets because of a `params` constructor mix-up.
68//! - `EnsureCreated` actually calls the creator in its loop; the C# loop never terminates.
69//! - [`InnerReferenceExistenceValidator::try_each_links`] exists because
70//!   [`Links::each_links`](crate::Links::each_links) has no error channel.
71//! - [`NoExceptionsDecorator`] maps `Err(_)` to [`Flow::Break`](data::Flow::Break), the
72//!   closest thing Rust's [`Flow`](data::Flow) has to C#'s `Error` constant. It does not
73//!   catch panics.
74//! - [`LoggingDecorator`] surfaces the first I/O error from the log writer instead of
75//!   discarding it.
